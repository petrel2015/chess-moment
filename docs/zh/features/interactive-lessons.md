# 互动棋课（Interactive Lessons）

## 概述

互动棋课是棋刻的核心形态：每篇课程把一段背景故事和一个 3–5 步的棋盘挑战结合，读者亲手走完关键步骤，每一步立即得到红绿反馈和讲解，走对后对手自动回应，完成后弹出复盘。

![互动挑战](../../img/challenge.webp)

## 背景

项目最初（2026-07-27 之前）的设想是「国际象棋每日推送」：公众号图文每日推送。纯图文的问题立刻显现——读者看完着法列表并没有真正学会，因为缺少「自己走、走错、被纠正」的闭环。

## 问题

初学者自学开局/残局材料时：

1. 静态着法列表无法验证「我是否真的会走」；
2. 走错了不知道错在哪，容易形成错误直觉；
3. 手机上缺少免注册、加载快、三分钟内能完成的练习载体。

## 目标

- 每篇课程 3–5 次关键选择，三到六分钟完成。
- 点击与拖动两条走子路径都要可用（手机触摸为主）。
- 每步即时反馈：正确（绿）、错误（红 + 一句解释）、合理但非最优（琥珀 + 讲解，不计进度）。
- 对手自动回应，模拟真实对局节奏。
- 页面自包含：单期 URL 分享后无需任何额外请求即可完整体验。

## 不解决的问题

- 不提供自由对局或人机对弈（对手回应是脚本化的每步一手）。
- 不做通用战术题库/按难度刷题（每天只推一篇）。
- 不做引擎级局面分析（胜算条是教学估算）。
- 不做跨设备进度保存。

## 解决方案概述

- 课程内容 JSON 内嵌为页面里的 `window.CHESS_LESSON`，共享的 `assets/app.js` 负责全部交互；没有框架和虚拟 DOM，直接 DOM 渲染。
- 棋盘渲染：64 个 `<button class="square">`，棋子为 `<img>` 贴纸素材；`<head>` 预加载 12 枚棋子图片避免首走闪烁。
- 走法合法性由 `assets/chess-engine.mjs` 在浏览器内判定；选中棋子后仅高亮合法目标格，非法走法根本点不进去。
- 反馈：`markMoveFeedback` 在目标格上挂绿/红圈（含动画环），1 秒左右自动消退；状态区同步显示讲解文字。
- 对手回应窗口：走对后进入 `awaitingOpponent` 状态锁住输入，对手走完自动解锁；回应走法会先做合法性校验，失败时明确报错并解锁，绝不把用户卡住。
- 候选着（`alternatives`）：命中时给琥珀讲解但不推进 `step`。
- 完成庆祝：全部走完后弹出庆祝提示，复盘区随时可见。

## 用户体验

- 状态区（`aria-live="polite"`）全程播报当前状态，进度点显示步数。
- 「给一点提示」「重新挑战」「反馈问题」三个按钮常驻。
- 棋谱记号（如 `Nxd4`）带悬停释义，初学者不用查记法表。

## 兼容性与历史影响

该功能是站点的基础形态，后续所有功能（胜算面板、候选着、标签、双语、教练）都是在其上的增量。2026-08-11 的对手回应窗口修复（`cb0ce71`）把「回应失败」从静默卡死改为显式报错 + 解锁，属于行为修正：此前用户可能停留在无反馈状态。除此之外没有破坏性变更；新增课程 JSON 字段均向后兼容（校验器对旧字段保持宽容）。

## 数据与隐私影响

全部在浏览器本地运行，无网络请求。拖动/点击不产生任何上报。

## 性能影响

单页只有一个棋盘与一次性内嵌数据，构建产物无框架运行时；棋子 PNG 经过 `scripts/optimize-pieces.mjs` 压缩（约 -91%），首屏预加载。

## 当前限制

- 每页一题，题目间无连续性（先修链接只是阅读顺序建议）。
- 对手回应只走预脚本的一手，不会惩罚读者的其他走法。
- 无进度持久化，刷新即重置。
