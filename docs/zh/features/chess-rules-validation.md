# 规则引擎与内容校验（Chess Rules Validation）

## 概述

「棋规由代码说了算」是本项目的第一设计原则。它由两层实现：构建期用 chess.js 对每期课程做真实棋规校验（不合法就拒绝发布），运行期用自研轻量引擎在浏览器里判定每一步走法。

## 背景

课程 JSON 里的每步正解和对手回应都是人（或模型）手写的。一旦写入一条在该局面不合法的走法，读者会走到一个「不可能」的局面，整个课程的公信力崩塌。初版（2026-07-28）校验覆盖格式与基本走法；2026-08-07（M2，`fbbd042`）引入特殊规则并抽出独立引擎。

## 问题

1. 手写 FEN 与 UCI 走法极易出错：升变忘写第 5 字符、易位写成车走法、对手回应与当前局面矛盾。
2. 浏览器端如果直接引入 chess.js（约 100KB+），与「轻量静态页」矛盾；但自研引擎必须被完整测试覆盖，否则比不用引擎更危险。
3. 校验失败必须让构建失败，而不是告警。

## 目标

- 构建期：每步正解、每个 `alternatives` 候选、每个对手回应都要在真实棋规下逐步实走验证；任何一处不合法即构建失败。
- 浏览器端：支持王车易位（含权限位）、兵升变（UCI 5 字符）、吃过路兵、将军/将死判定；纯函数、无 DOM、Node 可测。
- 校验器同时负责：字段完整性、FEN 结构、胜率三项和为 100、快捷问答配对、先修死链、slug 唯一。

## 不解决的问题

- 不做引擎评估（胜算数字是作者写入的教学估算）。
- 不做开局库/残局表。
- 不阻止作者写出「合法但质量差」的题目——质量靠人审。

## 解决方案概述

两层各自独立、职责清晰：

```text
构建期（Node）：content/*.json
  └─ scripts/validate-content.mjs ── 用 chess.js 逐步实走
       move / opponent / alternatives 全部验证，失败即退出

运行期（浏览器）：assets/chess-engine.mjs（自研，约 350 行）
  └─ parseFen / legalTargets / applyMove / inCheck / isCheckmate
       app.js 每次点击、每次对手回应都经过它
```

为什么浏览器不用 chess.js：站点交互只需要「当前局面合法走法生成 + 应用 + 将军判定」，自研实现更小且免去额外下载；而风险由 173 个测试中的引擎单元测试与逐课程走子回归（`tests/lessons-walkthrough.test.mjs`，把每课每步正解与对手回应实走一遍）兜住。chess.js 只出现在构建期与测试里，不进浏览器产物。

对手回应在浏览器里也会再次校验（`app.js` 防御逻辑）：即使数据被污染，用户也只会看到显式报错而不是被卡住。

## 详细行为

- UCI 记法：普通 4 字符（`e2e4`）；升变 5 字符（`e7e8q`，末位 `q/r/b/n`）；易位写王 from→to（`e1g1`）。
- FEN 第 3 段（易位权）与第 4 段（吃过路兵目标格）由引擎解析维护。
- 校验器输出 `文件名: 原因`（如 `duplicate slug`、`invalid FEN`、`odds ... do not sum to 100`），构建即失败。

## 兼容性与历史影响

- 2026-08-07 引擎升级后，早期课程中「格式合法但依赖宽松实现」的写法被逐步修正；`60ac119` 为每期课程补走子回归，此后任何课程数据改动都会被实走验证。
- 无运行时行为破坏：浏览器引擎的判定结果与构建期校验一致由测试保证。

## 数据与隐私影响

纯本地计算，无网络。

## 性能影响

自研引擎在 64 格问题上开销可忽略；构建期 chess.js 实走每课数十步，整个测试套件 17 秒左右完成（本地实测）。

## 当前限制

- 引擎未实现三次重复、50 回合、子力不足判和（课程时长内不会触及）。
- 校验器不校验文案质量、胜负声明与 odds 数值的合理性（除归一外）。
