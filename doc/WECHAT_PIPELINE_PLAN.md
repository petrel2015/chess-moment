# 棋刻公众号双版本流水线实施计划

## 目标

把现有单一互动页面扩展成“一份课程数据、两种阅读形态”：

1. 公众号版：纯文字、静态棋盘图、完整答案与讲解，适合微信正文。
2. 实战版：保留点击/拖动走棋、即时反馈、提示、复盘与术语解释。

公众号的“阅读原文”必须直接指向同一期实战页，而不是首页。

## 交付阶段

### 阶段一：内容契约与构建边界

- 保留 `content/*.json` 为唯一内容源。
- 为公众号所需的少量元数据定义可选结构，禁止复制整篇正文。
- 加强 FEN、行棋方、逐步走法与重复内容校验。
- 把公开站点基址改成可配置项，默认使用正式 Pages 地址。

### 阶段二：双渲染器

- 继续生成互动首页与每期互动页。
- 为每期生成公众号安全 HTML 预览。
- 为每期生成确定性的静态棋盘 PNG。
- 生成可供发布器消费的结构化 payload，不含任何凭证。
- 生成公众号预览索引，便于人工验收全部课程。

### 阶段三：微信发布适配器

- 封装 access token、正文图片上传、封面素材、草稿创建、提交发布和
  发布状态查询。
- 默认只允许 `dry-run` 或模拟服务器。
- 用日期与课程 slug 组成幂等键，避免同一期重复创建或重复发布。
- 对限流和瞬时网络错误进行有限重试；审核失败和权限失败不得盲目重试。
- 输出机器可读诊断结果和一条人类可读汇总。

### 阶段四：Hermes 运行手册

- 提供 Hermes + GLM-5.2 可直接执行的任务说明。
- 08:30 生成、校验、构建并部署互动页。
- 验证公开实战 URL 可访问后，09:00 才允许提交公众号发布。
- 在未配置公众号权限与凭证前，只能生成草稿 payload，不创建生产定时任务。

### 阶段五：验收与发布

- Hermes 编写实现和测试并执行完整测试。
- Codex 按 `WECHAT_PIPELINE_ACCEPTANCE.md` 独立验收。
- 发现问题后退回 Hermes 修复，直至全部门槛通过。
- 最后合并并推送到 GitHub Pages，验证公开地址。

## 非目标

- 不用浏览器自动化模拟公众号后台。
- 不在仓库保存 AppSecret。
- 不在没有账号权限时尝试真实发布。
- 不把公众号文章做成只有摘要的引流页。
- 本阶段不自动生成大量新课程，先让现有课程全部通过双版本流水线。
